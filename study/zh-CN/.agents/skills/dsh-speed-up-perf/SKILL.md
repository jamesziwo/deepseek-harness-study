<a id="speed-up-deepseek-harness"></a>
# 提升 DeepSeek Harness 性能

将“加快速度”的宽泛请求转为可复现用户路径测量和小范围证据修复。这是指导，不是配额或脚本；广泛调查，跟随实测成本，拒绝不能改善真实用户负载的诱人改动。

<a id="establish-scope-and-current-authority"></a>
## 明确范围与当前权威来源

阅读[根规则](../../../../../AGENTS.md)、[架构](../../../../../docs/architecture.md)、[测试策略](../../../../../docs/testing.md)、[防御模式](../../../../../docs/defensive-patterns.md)及受影响包说明和笔记。进程、时钟、浏览器和异步清理用 [CI 可靠性](../dsh-ci-test-reliability/SKILL.md)。

约定用户可见终点、负载范围、资源约束、可接受小行为差异和停止条件。后端与浏览器端到端分别测量；历史迭代／客户端 fold 快不证明传输、绘制、滚动或输入快。测本地开销排除模型／网络延迟时须说明，不能称完整产品延迟。

检查精确当前基线，不只看运行工作区。读最终合并差异、所属源码、测试及已解决线程，PR 正文可能描述被放弃实现。分清已合并、关闭未合并、被替代、估算和新实测。[性能流程证据](../../../../../.agents/notes/implemented/process/2026-09-06-evidence-driven-performance-skill.md)只是历史线索，不授权重新引入实现。

<a id="survey-user-paths-then-rank-candidates"></a>
## 先调查用户路径，再排序候选

广度有帮助时委托独立领域，要求测量和生产调用点，不要猜测。可选领域：

- 冷 profile 启动、首次历史读取、当前代次重开及可写恢复。
- 多轮及工具密集历史、单条大消息／结果、子 Session 列表和反复导航。
- 初次历史传输与 fold、浏览器首次可用绘制、旧页加载、滚动、工具展开及未活动视图激活。
- 实时流和重连，包括长活动尝试、交错工具工作、结算、取消和释放。

独立改变成本维度：字节、持久事件、紧凑记录、原始增量、轮次、工具、子级和可见 DOM 数不同。未检查压力对应用户动作前，不把大量微小同质消息称为真实负载。覆盖典型和长尾，但不建无决策价值的组合爆炸矩阵。

按实测用户延迟、CPU／分配、保留内存、频率和置信度排序。每项说明生产消费者、重复工作、预期复杂度、最小可证伪干预和必须稳定的行为；可疑循环、未用缓存或大文件本身不是瓶颈证据。

<a id="build-realistic-synthetic-benchmarks-first"></a>
## 先建立真实的合成基准

遵循[基准规则](../../../../../benchmarks/AGENTS.md)和[性能检查决策](../../../../../.agents/notes/implemented/testing/2026-09-04-session-open-performance-gate.md)。扩展已有必需通道，不另建竞争性校准／报告机制。包局部诊断随所有者，跨包必需用例按用户路径放 benchmarks/。

用户授权检查本地资料时只提取聚合负载特征。绝不把提示、输出、路径、身份、ID、凭据、录制或可识别片段复制到 fixture、日志、截图、PR、产物。固定输入从已审常量生成，基准不依赖用户 home、环境仓库、网络服务或私有数据。

实现前记录测量卡：

| 字段 | 必须明确的决定 |
|---|---|
| 用户操作 | 精确动作和外部可观察完成条件 |
| 负载 | 固定维度、分布、种子／常量，以及覆盖普通和长尾的理由 |
| 入口 | 生产调用／组合和构建产物，哪些外部边界被 mock |
| 时钟 | 包含的准备、冷／热状态、计时起止和排除成本 |
| 内存 | 终点可达对象、基线、GC 策略、保留与瞬态限制 |
| 判定 | 原始样本、聚合方式、校准绝对／比例／内存限制、反例对照 |
| 行为 | 所属功能测试／快照和允许的小差异 |

CPU worker 在普通 Node 测构建 JavaScript，源码加载器与解析开销不是交付路径。浏览器用构建资产和受支持 profile，通过已有测试框架运行；不为测量新增生产导出，也不复制算法成“基准实现”。

冷启动／进程内存样本用新子进程和私有临时根；热样本明确保留目标缓存，fixture 不能暗中预热冷情景。两边输入、校验、完成条件和可达输出相同；解析后丢弃不能与校验且保留历史相比。

报告全部样本及决定结果的聚合。Node 通道用已有共享时间校准和已审噪声余量，不按 CPU 速度缩放字节、数量、无量纲比例。人工浏览器诊断不设阈值；必需浏览器性能用例在采用预算前须明确通道并在真实 CI 重复测量，Node 机器倍数不等于浏览器校准。预算是源码常量，不是环境覆盖。测量工作与自身其他 CPU 重任务串行，参考与候选条件可比；不放宽预算或挑幸运样本隐藏回归。

端到端延迟与组件阶段独立测量。保留内存测量时保持预期对象可达，瞬态压力另用受限堆完成或适当峰值测量；执行更快但保留无界不自动算胜利。

浏览器响应性要真实输入并观察界面更新；帧／输入测量包含最后一次卡顿，区分定时器调度与真实输入，限制合成生产者避免追赶突发改变负载。说明是否覆盖首绘、滚动、分页、实时更新及已激活但隐藏视图。Node fold、假 DOM、自定义心跳本身不能证明浏览器响应性。

<a id="prove-the-regression-then-remove-work"></a>
## 先证明回归，再减少工作

改生产代码前运行未优化负载，保存命令、版本、运行时／平台、fixture 维度、原始测量和判定。缩小失败情景但保留真实瓶颈，修改前排序可证伪假设，用 profile、分配样本、工作计数或阶段计时区分。

以下值得测试，但不是自动处方：

- 下游保持紧凑表示；消费者只需最终内容或聚合时，避免每增量对象。
- 明确真实所有权／信任转换后才去重解析、复制、冻结和校验；同进程类型化借用不授权弱化持久或传输解析。
- 流式转换产物并限制中间状态，不保留每代；用户操作要求时纳入发布、验证和可写就绪义务。
- 分开只读准备与写入／发布，但不把正确性终点前必须等待的工作移到终点后。
- 延迟未活动视图和折叠细节，同时测首次激活及保留状态；延迟不是删除，视口高亮不是完整虚拟化。
- 稳定身份并缩窄订阅，避免单节点变化使全历史失效；保留更新顺序和即时事件行为。
- 用合适数据结构替代反复移位、扫描和重建；测完整消费者路径，不只测容器操作。
- 只有明确失效、有界保留、独立等待者取消和释放所有权时，才用修订键复用或 singleflight；不只为重复基准好看缓存膨胀表示。

每次只改一个因果因素，同时重跑定向和其端到端父情景。要求反例：收紧断言在原实现或受控重新引入目标成本时失败。回归仍能通过的宽阈值无保护，低于已核实噪声底的预算也不可靠。

<a id="preserve-behavior-and-resource-ownership"></a>
## 保留行为与资源所有权

性能补充而非替代功能证据。按需运行／添加输出、顺序、分页、流索引、错误、取消、并发和释放测试。保持模型可见与日志等价、已发布代次不可变、原子发布、必要校验和可写就绪；不为数字悄悄截历史、跳工具结果、禁不变量或改生命周期。

明确有意的小可见差异，并用所属无密钥快照验证。产品 GUI 变化需浏览器证据／GIF。功能预期独立于基准内部；基准断言只需足够证明到达真实终点，不另造一套语义测试。

端到端收益消失、典型负载明显回归、复杂度超过小收益，或取消／保留／持久性无法解释和测试时，拒绝优化。简述被拒假设，不扩大范围为其辩护。

<a id="deliver-a-bounded-reviewable-result"></a>
## 交付有界、可评审结果

长期理由、替代、校准、排除和风险遵循 [Agent Note 规则](../../../../../.agents/notes/README.md)。检查相关笔记替代关系，不把性能工作变成全库文字清理。可复用流程留在技能，情景事实留在基准或包所有者。

用户要求栈 PR 时，编辑前划分层次，使用官方栈及独立 worktree；每层可合并。基准基础设施保护测量基线，优化层携修复、功能覆盖和更紧预算。独立瓶颈可分栈，先在所属层修复发现再向上传播。

应用[推送前检查](../dsh-pre-push-checks/SKILL.md)，只报告实测证据，检查 CI，不假定本地时序证明 runner 稳定。ready 后按代码和可执行证据评估评审，说明理由或修复并解决已处理线程；不因报告来自机器人而忽视。

每项结果按“负载→前后绝对值及比率→终点和内存语义→行为证据→反例→精确检查→排除项”总结。区分作者历史报告、新本地测量和 CI 证据。在约定情景／修复范围停止，保留简短排序后续清单，不追无关机会。
