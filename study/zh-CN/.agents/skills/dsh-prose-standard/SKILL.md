<a id="deepseek-harness-prose-standard"></a>
# DeepSeek Harness 文字标准

先写足以保留契约的内容，再删除推理过程、重复和装饰。契约是调用方、被调用方、实现者、生产者或消费者依赖的义务、不变量、前后置条件或兼容承诺。本技能负责编辑判断和必要覆盖；位置、预算、双语和文档检查用 [dsh-doc](../dsh-doc/SKILL.md)，推理过程泄漏用 [dsh-trim-cot-leakage](../dsh-trim-cot-leakage/SKILL.md)。这是指导，不是脚本。

contract、boundary、shape、surface、seam、gate、vocabulary 使用前检查是否准确，不是禁词。先判断能否用精确规则、API、字段集合、类型、校验、时点、组件分工或失败表达更清楚；确实命名技术主题时保留，包括调用契约和安全／进程边界。

注释描述代码无法表达的非显然契约或理由，不复述代码已说明的内容。

<a id="inputs-and-exclusions"></a>
## 输入与排除范围

必须显式提供 scope；缺失时报告所需输入并停止，不推断全仓库范围或开始访谈。

mode 接受 automatic／interactive，默认 automatic；只有用户明确要求提问或校准时才交互。

mode 控制提问，不控制写权限。评审／审计只报告不编辑，明确要求写入、修复、精简时才应用清晰改动。

发现、评审、编辑始终排除 vendor/，即使用户要求全仓库，也不沿符号链接进入。排除放在包含 glob 之后，避免后续包含重新纳入；rg 末尾用 `--glob '!vendor/**'`，Git 用显式 `:(exclude)vendor/**`。范围只有 vendor 时报告无合格文件。

文字评审和修改也排除 .agents/notes/archived/。归档是冻结快照，只可为理解历史入站引用查看精确目标，不能更新文字或出站链接。

生成目录、快照和 fixture 属于派生内容。编辑前追踪所有消费者，源码 JSDoc 也可能生成模型可见目录；先改所属源码／情景，再重建全部派生物。生成器提取摘要时，该句必须对目标接口完整。双语无永久主语言，任一边可为本次来源；按[轻量流程](../../../../../docs/AGENTS.md#writing-rules)最小更新另一边并重录。

<a id="preserve-the-complete-proposition"></a>
## 保留完整命题

编辑前识别全部命题，保留相关的：

- 主体和动作；
- 条件、时机及顺序；
- 必须、可以、绝不等义务强度；
- 否定性保证及例外；
- 所有权、副作用、失败模式及后果。

只有全部事实子句保留且更清楚时才删形容、重复和叙述；字数更少本身不算改进。

在使用处保留调用方／维护者所需完整本地契约：行为、失败、所有权、后果。架构、理由、算法、历史和长例子积极链接唯一所属文档；解释只保留一份，但必要契约可在本地重复。

省略非显然理由可能导致误用或错误简化时保留，否则只写后果并链接理由来源。

<a id="required-coverage-by-prose-location"></a>
## 各位置的必要覆盖

这不是单向删字。代码、类型和结构未表达下列契约时补充／恢复文字；当地已显然时不加注释。

- **公开 JSDoc：** 调用方可见返回区别、抛错／拒绝、副作用、所有权、时机、取消和持久性。
- **内部注释：** 说明非局部结构及明显复杂的局部结构，包括不变量、竞态顺序、所有权、安全边界及意外失败；删除控制流叙述和代码复述。
- **模块注释：** 说明角色、依赖、责任及非显然架构选择，链接所属理由。
- **测试：** 只解释非显然设计，如 fixture、断言、平台适配、真实入口或间接观察为何必要，删除逐步讲解和清单。
- **操作指南：** 包含前置条件、必需动作、真实入口、可观察验证及简短警示。
- **README：** 包含消费者契约：配置、语义、失败、限制、扩展点、模型可见影响。引用包拥有的稳定模型文字，链接生成目录及跨包所有者；保留长期缺口和维护陷阱，不列日常清理。遵循[包 README 要求](../../../../../docs/cookbook/adding-a-package.md#4-write-the-package-readme)。
- **Agent Notes：** 保留独特理由、机制、替代方案、后果、交付验证及具名覆盖缺口。implemented 用现在时描述实际交付，删计划检查表，不删固定决策的证据。
- **事故复盘：** 保留事件顺序、证据、因果链、影响和预防；删除重复说服及不建立因果的细节。
- **技能／代理指令：** 写行为约束和明确范围，如“指导，不是脚本／完整清单”；工作流简洁并链接权威来源。
- **示例及配置注释：** 说明访问限制、非显然连接／加载顺序、安全立场、重放、例外和可能误用，不叙述配置已展示的条目。
- **提示词及可见字符串：** 文字就是行为。客户端文案归类型化语言词典，以显式本地化 props 交给不依赖 Cordis 的基础组件；一起检查文本、无障碍名称、tooltip、placeholder 和格式模板，再跑 verify-client-ui-i18n。更新所属模型可见可执行快照及仓库要求的 GUI 证据。授权范围无所属情景时保持文字并报告延后，不暗中并入纯文字编辑。
- **诊断：** 指明失败对象／路径、违反规则及非显然修正方式，删内部执行叙述。

保留可搜索机制名和有意义的义务、时间及否定强调，只规范装饰性强调。

<a id="workflow"></a>
## 工作流

1. 确认 scope、mode、当前分支或 PR 基线及适用 AGENTS.md，不检查无关分支。
2. 判断段落前读[文档标准](../../../../../docs/AGENTS.md)及所属代码／文档；校准或陌生情况读[提炼示例](references/examples.md)。
3. 检查请求范围而非只看大文件，用搜索和字数找候选，再做语义判断。
4. 分类为保留、添加、精简、恢复、重构或延后；只有任务授权才编辑，不为删除目标制造改动。
5. 先更新所有者，再改派生产物；学到新规则后复查类似段落。
6. 运行窄范围检查、文档检查、git diff --check，以及可见字符串行为测试。确认最终差异无 vendor 路径；误匹配时如实报告，不谎称始终干净排除。
7. 报告检查范围、明确修改、有意保留、延后案例及实际命令。

<a id="borderline-decisions"></a>
## 临界决定

只有至少两个版本都保留完整命题、但在已接受原则间取舍，且技能未解决该取舍时才算临界。只有一种保留命题答案的重写不算。

自动模式中，获授权的明确编辑直接做，真正临界情况报告而不提问；不能削弱命题以推进。

交互模式按原则分组相似段落，提供两三种可行版本、推荐一个并说明事实／结构差异，不给劣质陪衬。使用用户要求的渠道；通过 PR 行内评论校准时，差异中放推荐临时版本，替代方案附在精确行。

用户决定后，将原则和版本提炼进[示例](references/examples.md)，不留 PR 历史或评审叙述，并应用到范围内所有同类段落。
