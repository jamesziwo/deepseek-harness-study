<a id="ci-flake-diagnosis"></a>
# CI 偶发失败诊断

仅用于调查已有概率性测试或 CI 失败。保持用户要求的读写范围；诊断不授权修复、重跑工作流或改变 CI 配置。

<a id="freeze-the-evidence"></a>
## 固定证据

记录仓库、工作流、任务、提交 SHA、runner 标签、时间戳、精确失败测试／命令及首个稳定失败特征。基础设施消息与测试输出分开。

比较多次失败和成功运行，优先同 SHA；不可能时确认相关测试和 CI 配置在比较提交间相同。一次重跑通过不证明基础设施故障，一次超时不证明产品竞态。

用 Actions 日志和元数据确认失败是否在同宿主或资源命名空间重叠。保留运行链接，不粘贴大段日志。

<a id="classify-the-failure"></a>
## 失败分类

根据记录的证据分类，不根据最终采用的修复倒推：

- **宿主资源冲突：** 独立进程或任务取得同一端口、socket、数据库、可预测路径、缓存或外部命名空间。
- **生命周期不完整：** 子进程、worker、流、服务器或回调尚未结束，释放已返回，迟到输出或修改影响其他测试。
- **进程全局污染：** 结果依赖测试顺序，或泄漏的环境变量、cwd、假定时器、全局值、mock、区域或模块状态。
- **负载敏感同步：** 用 sleep、轮询间隔或假定事件循环轮次替代可观察就绪／完成。
- **平台或入口不匹配：** 失败稳定跟随操作系统、shell、文件系统规则、源码／构建模式或入口。Windows 与 POSIX 的时间戳精度、环境变量名大小写、句柄释放时机和权限语义不同，macOS 通过不证明 Windows 通道正常。
- **产品并发缺陷：** 测试控制自身资源，通过显式重叠确定性复现，暴露交付行为中的竞态。
- **外部提供方临时故障：** 失败归属真实 API／网络边界，符合其文档重试策略。
- **Runner 基础设施：** 检出、依赖下载、磁盘、宿主进程或 runner 服务独立于测试命令失败。分类前必须有直接证据；自托管池无指标时说明限制，并依据日志分类。同一特征在同池无关分支重复，是共享宿主争用证据，即使无法检查宿主。

证据支持多个独立事实时分别报告，不把超时、信号、退出码和断言混成一个推测结果。

<a id="reproduce-the-smallest-relevant-topology"></a>
## 复现最小相关拓扑

从所属测试文件或用例开始，只增加到首次复现特征的并发层级：

1. 一个测试进程；
2. 并发测试或文件；
3. 多个独立 Vitest 进程；
4. 使用配置 worker 数的所属仓库检查；
5. 共享问题宿主资源的独立任务或 runner 进程。

匹配当前 Vitest 配置、环境开关、源码／构建模式和平台；不要降低生产超时或加随机负载，刻意制造另一种失败。

若本机无法运行失败所属平台，复现阶梯停在可达层。记录限制，不用其他平台通过替代；随后以 CI 复现，每轮只修改一个怀疑归属方，保持可归因。

怀疑竞态时，用争用转换处的屏障替代随机时序；怀疑宿主冲突时，证明同时取得同标识，或证明原子唯一分配消除冲突。

<a id="fix-at-the-owner"></a>
## 在责任归属处修复

实现获授权时，修复负责分配、发布就绪、修改全局状态或释放的组件；不要把失败藏进快照规范化、重试包装器、更宽超时、全局串行或弱断言。

稳定 fixture 数据与真实资源分配分开：录制 URL 可固定，而 fixture 把传输映射到系统分配端口；稳定预期路径可保留为断言，而不成为共享写目录。

<a id="close-the-investigation"></a>
## 结束调查

满足以下条件时证据完整：

- 原始失败特征有证据支撑的分类；
- 最小相关拓扑可复现，或外部证据充分且明确复现限制；
- 获授权修复在反例或修复前状态失败，修复后同拓扑通过；
- 资源所有者要求的并发进程、恢复或完全释放证据通过。
- 其他 Actions 检查按观察状态报告为通过、待完成、跳过或失败。

不要一直重跑到偶然通过就称其稳定。选定证据已支持结论时停止，否则报告阻碍分类的缺失事实。
